## 1. 完整度门槛

### 1.1 结论

**只有「原题」是绝对必需项。** 其余一切为可选，缺失时引导而非阻断。

| 字段 | 地位 | 缺失时的处理 |
|---|---|---|
| 原题（题干/图片） | **必需** | 无法诊断，退回输入引导 |
| 学生作答 | 可选 | 降级为 L1 题目画像，同时用「常见错法清单」引导补作答 |
| 正确答案 | 可选 | 可自行推断；无则错因结论标注置信度较低 |
| 解析 | **可选对照** | 用户给了作为参考，**不参与完整性判定** |

### 1.2 为什么解析不是必需项

学生手上最不可能有解析，而解析恰恰是本系统该产出的东西。把解析当输入门槛，等于把大部分真实用户挡在门外。

> 注：`doc/diagnose-file-intake.md` 中的四类标签（origin / wrong / correct / analysis）是**上传时的分类标签**，继续保留；但**完整度判定口径以本文为准**，只看前两类与「是否有作答」。

### 1.3 证据可信度（作答与自述冲突时）

**不设「作答一律优先」这种绝对规则。** 作答证据本身的来源不同，可信度就不同；本地 OCR 对手写、分式、根式、上下标的识别错误率显著高于文字输入。

| 证据来源 | 可信度 | 冲突时的处理 |
|---|---|---|
| 学生自己打字的作答 | 高 | 以作答为准，自述递补 |
| 学生口述 / 复述 | 高 | 同上 |
| 多模态模型直接读图 | 中 | 回显让学生确认 |
| 本地 OCR 识别出的文字（尤其中文手写、公式、几何标注） | 中低 | **优先怀疑识别** |

四条处理规则：

1. **不判真假，先回显。** 冲突时不说「你错了」，而是「我识别到的作答是 X，对吗」。
2. **低置信强制确认。** OCR 置信度低于阈值时必须先确认才进诊断，禁止静默往下走。
3. **改口即准。** 学生改了，以新值为准；旧值仅留痕，不参与归因。
4. **「作答优先」只适用于文字输入。** 不得外推到识别结果。

> 这条规则同时是无障碍设计：手写体、拍照倾斜、光照差都会提高误识别率，静默推断会把误识别当成学生的真实错误，伤害最大的是最需要帮助的那部分用户。

## 2. 两段式诊断（L1 / L2）

由于原题是唯一必需项，诊断必须能分两级输出：

| 层级 | 触发条件 | 输出内容 | 教学价值 |
|---|---|---|---|
| **L1 题目画像** | 只有原题（或无作答） | 考点清单、常见错法清单、自查清单 | 即使没作答也有价值；且「常见错法」本身就是最好的补问话术 |
| **L2 错因归因** | 有学生作答（或学生自行描述错法） | 具体错因、策略卡、分级提示 | 完整诊断 |

### 2.1 L1 的补问话术

不要问「请提供你的答案」，要问：

> 这道题常见的错法是 A / B / C，你是哪一种，还是都不确定？

把「索取信息」变成「提供价值」——用户即使不答，也已经拿到了 L1 的内容。

### 2.2 用户拒绝补充时

输出 **L1 题目画像 + 一句声明**：

> 未提供作答，本次不做错因归因。

不给假错因，也不空手而归。

## 3. 错因枚举表（数学 v1）

错因是**有限枚举**，这是整个设计的基石：直查比检索准，也比检索省。

| code | 标签 | 典型表现 | 是否知识性 |
|---|---|---|---|
| `misread` | 审题不清 | 漏条件、看错问句、看错符号 | 否 |
| `pure_guess` | 纯粹选错 | 会做但勾错，无知识断点 | 否 |
| `calc_error` | 计算失误 | 算术、符号、移项、约分 | 否 |
| `transcribe` | 抄写错误 | 从题干抄下来就抄错 | 否 |
| `concept_confuse` | 概念混淆 | 定义理解错误 | 是 |
| `formula_misuse` | 公式误用 | 记错公式或超范围使用 | 是 |
| `hidden_cond` | 隐含条件遗漏 | 定义域、分母非零、根号非负、判别式条件 | 是 |
| `case_miss` | 分类讨论遗漏 | 含参数问题漏分支 | 是 |
| `step_jump` | 步骤断层 | 中间步骤无依据地跳过 | 是 |
| `modeling_error` | 转化/建模错误 | 应用题列式错、图形转代数错 | 是 |
| `boundary_error` | 边界处理错误 | 端点取闭/开、不等式方向 | 是 |
| `graph_misread` | 图象误判 | 读图看错交点/单调性 | 是 |
| `unit_error` | 单位/量纲错误 | 单位未统一、量纲不对 | 否 |
| `answer_off_target` | 答非所问 | 算出来了但没回答题目问的 | 否 |

### 3.1 主错因与次错因

一次归因允许输出 1 个主错因 + 最多 1 个次错因，主错因必须带置信度（0~1）。不准输出三个以上——那是没归因。

## 4. 错因 → 策略卡

**关键设计**：策略不因题目而异，因此按错因**直查**，不做检索。

| 错因 code | 干预策略（要点） |
|---|---|
| `misread` | 划线法：圈条件、圈问句、圈单位；读完后用自己的话复述一遍题目 |
| `pure_guess` | 不补知识，改检查习惯：控制时间分配、留出复核窗口、结果代回验证 |
| `calc_error` | 分步验算；符号单独走一遍；把结果代回原式 |
| `transcribe` | 抄写后逐项比对题干；养成「抄完回头看一眼」 |
| `concept_confuse` | 定义对比表（易混概念并排列）；用反例辨析边界 |
| `formula_misuse` | 写出公式适用条件清单，用前先核对条件是否满足 |
| `hidden_cond` | 三步检查：分母 ≠ 0 / 根号内 ≥ 0 / 对数真数 > 0；函数题先写定义域 |
| `case_miss` | 参数扫描清单：正/负/零，或按判别式符号分档，逐档讨论 |
| `step_jump` | 每一步写依据（用了哪个定理/公式），写不出依据的那步就是断层 |
| `modeling_error` | 先写「已知→所求」的对应关系再列式；用特殊值检验式子合理性 |
| `boundary_error` | 单独检查端点：能否取等、方向是否反、开闭是否对应 |
| `graph_misread` | 先在图上标出所有关键点（交点、顶点、端点）再读数 |
| `unit_error` | 解题前统一单位；答案必须带单位；做量纲自检 |
| `answer_off_target` | 收尾三问：题目问什么？我算的是什么？要不要带单位/范围？ |

## 5. 提示阶梯

| 级别 | 内容 | 约束 |
|---|---|---|
| L1 定位 | 这题考什么知识点、属于哪类题型 | 不含任何算式 |
| L2 方向 | 第一步该做什么、该用哪个工具（定理/公式） | 不给具体算式 |
| L3 关键步骤 | 给出卡住的那一步的关键推导 | 不写完整解答 |
| 完整解 | 全流程解答 | 仅在 L3 之后、用户明确要求时给出 |

**默认停在哪一级**：L1，由用户点「继续」逐级下降。任何一级都允许用户直接要答案，但系统必须先完成 L1/L2 的诊断输出。

## 6. 输出结构

```ts
interface DiagnosisResult {
  subject: 'math'
  level: 'L1' | 'L2'
  completeness: {
    hasProblem: boolean
    hasStudentAnswer: boolean
    hasCorrectAnswer: boolean
    hasAnalysis: boolean
  }
  knowledgePoints: string[]                       // 考点，1~3 条
  errorCause: {
    code: string                                  // §3 的 code
    confidence: number                            // 0~1
  } | null                                        // L1 时为 null
  secondaryErrorCause?: { code: string; confidence: number }
  strategy: StrategyCard | null                   // L2 才有
  hints: Array<{ level: 1 | 2 | 3; content: string }>
  notes?: string                                  // 如「未提供作答，本次不做错因归因」
  strategyVersion: number                         // 与 §4.1 的 version 对齐
}
```

**对话模式与诊断模式共用此结构**，差别只在渲染层与批次粒度——不写两套提示词。

## 7. 输出纪律：诊断不是解析

这是本项目最容易被大模型做坏的地方。**模型收到「帮我看看这道题」，默认行为是讲一遍正确解法，然后在末尾补一句「你的问题在于中间算错了」。那仍然是在讲解析，不是在做诊断。**

因此此处不做交互拦截（不设「必须点过 L1 才能要答案」这类关卡），只做提示词层的输出纪律约束。

### 7.1 三条禁令

| 禁令 | 说明 |
|---|---|
| 不得直接给答案 | 未完成定位前，答案不得作为首个输出 |
| 不得只给答案 | 答案可以给，但必须挂在错因之后；只给答案等于放弃诊断 |
| **不得整段复述正确解法** | 唯一真正需要守的一条。复述解法是解析，行为上等价于搜题工具 |

### 7.2 正反对照

| ❌ 解析（禁止） | ✅ 诊断（要求） |
|---|---|
| 「这道题第一步先把方程化成标准形式，得到 …，最后 x = 3 或 x = -1」 | 「你写到 x = 3 就停了。你解的是二次方程，但只取了一个根，另一个根哪去了？」 |
| 「正确的思路是先用判别式判断根的个数」 | 「你用了判别式，但只算了 b²-4ac 的正负，没算它的具体值，所以两个根只能定一个范围」 |

差别只有一个：**解析从题目出发，诊断从学生的作答出发。**

### 7.3 机械判据（可自动化检查）

为使禁令可验证，规定：**每次 L2 输出必须引用至少一处学生作答的原文片段**（引自 OCR 结果或学生输入，逐字或近似）。

- 未引用任何作答片段 → 视为疑似解析，自动重试一次（不消耗追问预算）。
- 重试仍未引用 → 降级输出 L1 题目画像，并说明「未能定位具体断点」，不硬编错因。

判据的实现成本很低（子串/近似匹配），但它是这套产品与搜题工具的分界线，建议做成后置校验而非只写进提示词。
