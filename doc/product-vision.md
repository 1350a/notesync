## 0. 约束强度（先读这一节）

**本文及同组协议（`diagnosis-model.md`、`agent-workflow.md`、`safety-protocol.md`、`implementation-status.md`）描述的是理念与方向，不是逐条必须遵守的实现契约。** 实现时允许偏离，但偏离要满足两个条件：

1. 知道自己偏离的是哪一条；
2. 偏离后的行为仍符合该条的理念。

| 级别 | 含义 | 可否改 | 例 |
|---|---|---|---|
| **H 硬** | 违反即缺陷，评审与门禁都要挡 | 不改 | 不把学生数据无提示送出设备；未实装能力不在界面出现；类型纪律 |
| **D 方向** | 理念必须守，数字 / 形式 / 命名可改 | 可改，说明理由即可 | 提示阶梯「必须分级」要守，三级改四级无妨；追问「必须有预算」要守，2 轮改 3 轮无妨 |
| **A 假设** | 基于推测，实测后大概率调整 | 预期会改 | 置信度由模型自评是否可信；OCR 确认阈值取多少；机械判据用子串还是近似匹配 |

## 1. 一句话定位

**一个错因驱动的学科诊断系统：不替你解题，先定位你为什么会错，再按需给出分级提示。**

与「拍照搜题」类产品的差别：

| 维度 | 搜题工具 | 本项目 |
|---|---|---|
| 首要输出 | 答案 | 错因 |
| 交互假设 | 用户要答案 | 用户要理解 |
| 失败形态 | 给错答案 | 给错归因 |
| 数据边界 | 上传图片到云端 | 本地识别优先，可不上传 |

## 2. 目标与非目标

### 目标（v1）

- 初中／高中数学**单题诊断**：原题 → 考点定位 → 错因归因 → 分级提示。
- 整卷诊断：上传整卷，输出逐题诊断与汇总报告（见 `agent-workflow.md` §5）。
- 图片优先的输入（手机拍题），本地识别与多模态识别双通道。
- 全流程可解释：每一步诊断都能说明依据。

### 非目标（v1 明确不做）

| 项 | 原因 |
|---|---|
| 英语学科 | 题型内差异大（词汇/语法/阅读/写作），错因可枚举性差；架构预留，实现后置 |
| 写作、听力 | 无唯一答案或需音频链路 |
| 用户账号体系 | 本地存储足够；避免持有学生个人数据 |
| 本地大模型生成 | 端侧只做感知（识别）与表示（嵌入），生成在云端 |
| 外部 MCP server | 同源部署、无跨进程鉴权需求，Function Calling 已覆盖（见 §5） |
| 视频模态 | 与场景无关 |

## 3. 主流程

```
进入应用
  └─ 默认档（质量模式 + 本地识别优先），不做首屏偏好采集
       ├─ 单题诊断（对话式）
       │    ├─ 输入：原题（必需）、学生作答（可选）、正确答案（可选）、解析（可选）
       │    ├─ 完整度判定 → L1 题目画像 / L2 错因归因
       │    └─ 提示阶梯分级给出，用户主动要才继续
       └─ 整卷诊断（批量）
            └─ 切题 → 分类 → 逐题诊断 → 汇总报告
```

### 3.1 为什么取消首次引导

原设想是首次进入时选「效率/质量」「本地/云端」。已取消，理由：

1. 用户此时不知道两者差别，选择没有信息量；
2. 首屏多两步决策，推高流失；
3. 让用户为「未知的成本差异」做不可逆选择，是设计上的越权。

替代方案：默认给保守档（质量模式 + 本地识别优先），在**第一次真实诊断**时以可切换形式暴露，并附一句差异说明；设置页可随时改。

### 3.2 为什么取消「发个你好测模型是否在线」

判断模型可用性是工程职责，不是用户任务。后台已有模型探测（带缓存），失败时在输入区提示即可。

### 3.3 主线选择与演示对象

**对话模式是主线，整卷是批量上传入口。**

- 单题对话才体现「错因」的差异，也是评委能在 3 分钟内看懂的部分；
- 整卷承担规模能力展示（切题 → 聚类 → 同类共享 → 汇总），作为「另有此能力」出现，不占演示主线时长；
- 两者共用同一套 `DiagnosisResult` 与提示词，不写两套。

**演示对象：比赛评委。** 一切优化以「3 分钟能让人看懂我们在做诊断而不是搜题」为准。因此：

| 优先级 | 项 |
|---|---|
| 高 | 诊断 vs 解析的差异肉眼可辨（见 `diagnosis-model.md` §7.2 的正反对照） |
| 高 | 错因与策略卡可见、可解释 |
| 中 | 本地识别不上传的证据（一句话说明即可，不必做演示） |
| 低 | 整卷流程完整性、界面美观 |


## 4. 设计原则

### P1 错因优先于答案

首轮输出不包含完整解答。答案只作为诊断完成后的可选产物，且必须由用户主动索取。

### P2 提示阶梯

三级递进：定位（考什么）→ 方向（怎么想）→ 关键步骤。每级需用户确认才降级。

### P3 追问有预算

追问轮数上限固定（默认 2），每次追问必须绑定一个**可验证的推测**，不接受「你哪里不会」这类开放式提问。预算耗尽强制收敛出结论。

### P4 设备边界与图片路径自动路由

不把学生数据送出设备是**可选**的降级路径；**一旦要送出，必须显式提示并获同意**。

图片路径按**所选模型能力自动路由**，不再提供人工档位选择（2026-11-14 拍板，替代旧
「全本地 / 多模态 / 混合」三档手选）：

| 所选模型 | 图片处理 | 外发内容 | 代价 |
|---|---|---|---|
| 多模态（`acceptsImages`） | 原图直传，**无转写** | 图片（及文字） | 图片上传至模型服务商 |
| 纯文本 / 能力未知 | OCR 转文字后发送（引擎见 doc/cloud-ocr.md §4） | 仅转写文本 | 丢失版面与图形信息；云端引擎时像素上传至智谱 |

约束：

1. **外发的代价必须写在发送处**（触屏无 hover）：多模态档写「图片将上传至模型服务商」；云端 OCR 档写「图片像素上传至智谱」。
2. **路由只看模型能力，不存在混合档**：旧「混合」（OCR 打底 + 原图同传）已下线——不做「又是 OCR 文本又是原图」的双重上行；服务端组装对旧历史重发保留兼容（browser-local-ocr.md §6.2）。
3. **转写引擎默认云端（2026-11-14 拍板，替代旧「默认全本地」约束③）**：质量优先；设置页「图片处理（OCR）」行即同意面——代价文案随引擎派生，切「本地」是隐私动作。旧存量 `preferLocal` 键由 normalize 丢弃（user-settings.md §2）。
4. **能力未知按纯文本处理**（保守转文字，绝不赌上游能不能吃 image_url）。
5. **OCR 失败阻断发送**，绝不静默丢图、绝不静默换引擎（browser-local-ocr.md §6.4）。

### P5 不撒谎

未实装的能力不以可用形态呈现（见 `AGENTS.md §8`）。文档中标注「未实装」的功能，界面上不得表现为已生效。

## 5. 技术选择与理由（答辩可用）

| 选择 | 理由 |
|---|---|
| 用 Function Calling，不用外部 MCP server | 同源进程内调用，无跨进程鉴权与序列化成本；协议要求为「MCP **或** Function Calling」 |
| 错因用标签直查，不用向量检索 | 错因是有限枚举，直查更准、零检索开销、结果稳定 |
| 本地只做 OCR + 嵌入，不做生成 | 端侧负责感知与表示，生成仍需云端模型；诚实分层优于宣称「全本地」 |
| 不用账号系统 | 减少个人数据持有面，本身即隐私设计 |
| Next.js API Routes 仅做校验与委托 | 后端是 AI 接入层，不是业务系统 |
